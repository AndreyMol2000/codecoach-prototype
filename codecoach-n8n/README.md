# CodeCoach агент в n8n

**[Пошаговая инструкция по запуску n8n из корня репозитория](../N8N_START.md)**

Учебный проект Молчанова Андрея Владимировича для задания «Сборка ИИ-агента с помощью n8n» по дисциплине «Стартап-экосистемы».

Отдельный веб-чат принимает вопрос по JavaScript. Настоящий workflow n8n проверяет ввод, подбирает учебный контекст, вызывает локальную Qwen и возвращает сгенерированную подсказку пользователю. Ответ не хранится в исходниках и не подменяется заготовкой при ошибке модели.

## Компоненты

- **n8n Community Edition 2.44.7** — workflow из 13 функциональных нод.
- **Qwen3-1.7B, Q8_0** — бесплатная локальная модель под лицензией Apache 2.0. API-ключи и облачная квота не нужны.
- **llama.cpp b11669** — локальный сервер модели с OpenAI-совместимым HTTP API.
- **Node.js 22–24** — отдельный веб-чат и его HTTP-прокси.

Это самостоятельный второй учебный проект. Прежний прототип CodeCoach с тестами и наставником на правилах не заменяется этим workflow.

## Сценарий

1. Пользователь открывает веб-чат, выбирает уровень помощи и отправляет вопрос с коротким фрагментом кода.
2. Чат делает POST в свой сервер; сервер пересылает вопрос в production webhook n8n.
3. n8n нормализует ввод, проверяет ограничения и выбирает тематическую учебную справку.
4. n8n формирует сообщения `system` и `user`, затем вызывает `/v1/chat/completions` локальной Qwen.
5. Из ответа модели извлекаются объяснение, проверочный вопрос и статистика токенов.
6. Проверенный ответ возвращается в веб-чат. Пользователь видит результат, время, число токенов и requestId.

Уровни помощи: 1 — намёк и вопрос; 2 — объяснение причины; 3 — алгоритм словами; 4 — пользователь разрешает готовый код. Это инструкции модели, а не формальная гарантия соблюдения: компактная LLM может ошибаться или давать помощь глубже выбранного уровня.

Каждый запрос независим. Многоходовая память не реализована. Пользовательский JavaScript не исполняется, результаты запуска и тестов модель не получает. Модель предназначена для учебного разбора и не заменяет проверку кода.

## Структура workflow

| № | Нода | Назначение |
|---|---|---|
| 01 | Web chat request | Внешний POST из веб-чата |
| 02 | Normalize input | Нормализация, длина, глубина помощи, requestId |
| 03 | Valid question? | Ветвление по корректности ввода |
| 04 | Learning context | Учебная справка по теме вопроса |
| 05 | Check numeric example | Безопасный разбор числового JSON-массива, проверка максимума и минимума |
| 06 | Build model request | System-промпт, текущий вопрос, проверенные факты, формат результата |
| 07 | Qwen real LLM call | Реальный HTTP-вызов языковой модели |
| 08 | Parse model response | Разбор ответа, токенов и метаданных |
| 09 | Answer generated? | Проверка наличия результата модели |
| 10 | Format answer | Подготовка ответа каналу |
| 11 | Reply to web chat | JSON-ответ пользователю |
| 12 | Invalid input | Ошибка 400 без вызова модели |
| 13 | Model unavailable | Ошибка 503, если модель недоступна |

По успешной ветке проходят 11 нод. Подключение модели реализовано через стандартный HTTP Request, а не через встроенную чат-симуляцию. Ответ генерируется Qwen по полю `question`; узел обработки не содержит заранее подготовленного ответа на вопрос пользователя.

## Запуск на подготовленном компьютере

Откройте PowerShell в папке проекта:

```powershell
.\scripts\start.ps1
```

Адреса:

- Веб-чат: **http://127.0.0.1:3010**.
- Редактор n8n: **http://127.0.0.1:5678**.
- Сервер модели: `http://127.0.0.1:8081`, открыт только на этом компьютере.

Если политика PowerShell запрещает запуск, можно применить разрешение только к этому процессу, предварительно прочитав скрипт:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start.ps1
```

## Установка из архива на Windows x64

Нужен Node.js 22–24, интернет для первой установки, несколько гигабайт свободного места и память для n8n и модели. Для первой установки будет скачано около 1,83 ГБ весов, 20 МБ llama.cpp и зависимости n8n. На медленном диске установка n8n может занять заметное время.

Из папки проекта выполните:

```powershell
.\scripts\setup.ps1 -RuntimeRoot "$env:USERPROFILE\Documents\Codex\work\n8n-agent-runtime"
.\scripts\start.ps1
```

Короткий путь RuntimeRoot помогает избежать ограничений Windows на вложенные имена. Скрипт проверяет SHA256 модели и llama.cpp. Глобальные npm-пакеты не устанавливаются.

В новом экземпляре n8n завершите первоначальную настройку локального владельца. Импортируйте `codecoach-workflow.json` через меню импорта в редакторе. Либо выполните `scripts/import-workflow.ps1`. Откройте workflow и опубликуйте его: нужен зарегистрированный **production** webhook, а не только тестовый запуск в редакторе.

После импорта проверьте URL в ноде 07: `http://127.0.0.1:8081/v1/chat/completions`. Такой адрес подходит, когда n8n и модель запущены на одном Windows-хосте. В Docker адрес нужно адаптировать под доступ к хосту; эта поставка запускается без Docker.

Если порт 5678, 8081 или 3010 занят другим сервисом, согласованно измените скрипт запуска, URL модели в workflow и адрес webhook в переменной `CODECOACH_WEBHOOK` веб-сервера.

## Проверка через реальный канал

Откройте веб-чат отдельно от редактора и задайте два разных вопроса:

1. «Почему let max = 0 даёт неправильный максимум для массива [-9, -4, -12]?»
2. «Чем отличается return от console.log в функции JavaScript?»

Покажите, что ответы относятся к разным запросам. В n8n откройте Executions и соответствующий запуск, затем ноду 07: на входе виден конкретный вопрос, на выходе — `choices`, `usage` и сгенерированный текст. Совпадение requestId в результате помогает связать ответ с запуском.

При остановленной модели сервис должен показать ошибку, а не выдать заготовленную подсказку. Неверный или слишком длинный запрос не должен доходить до LLM.

## Скринкаст для сдачи

Покажите редактор n8n с полным workflow, внешний веб-чат, отправку вопроса и реальный ответ. Затем покажите соответствующее выполнение и выход ноды модели. Подробный план: `docs/VIDEO_PLAN.md`.

Для локальной демонстрации веб-чат работает в отдельном браузерном канале. Для удалённого доступа преподавателя нужен HTTPS-адрес веб-чата: локальный `127.0.0.1` на другом компьютере не откроется. Не публикуйте редактор n8n или порт модели без отдельной настройки доступа.

Ссылка для обратной связи из задания: https://disk.360.yandex.ru/i/eZ6UpmfgZrpidA. Подготовка файлов и локального видео сама по себе не означает, что ссылка внесена в эту таблицу.

## Проверки и файлы

```sh
node --test
node scripts/build-workflow.mjs
```

`src/agent-logic.mjs` содержит обработку данных; генератор вставляет те же функции в Code-ноды JSON. После изменений логики пересоберите JSON и повторно импортируйте workflow.

Фактические результаты проверки и ограничения: `docs/CHECKS.md`. Данные для сдачи: `СДАЧА.md`.

Файлы `.local-runtime.json`, `.local`, база n8n и веса модели не должны попадать в публичный репозиторий или экспорт workflow. В JSON workflow нет API-ключей и паролей. История выполнений n8n содержит вопросы и ответы; не отправляйте туда секреты и персональные данные.
