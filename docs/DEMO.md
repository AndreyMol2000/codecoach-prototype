# Выступление на предзащите CodeCoach

Докладчик: **Молчанов Андрей Владимирович**. Продолжительность: около 4–5 минут, включая демонстрацию.

## Подготовка

Запустите `node server.mjs`, откройте `http://127.0.0.1:3000`. Проверьте запуск кода заранее. Для выступления используйте отдельную сессию, а перед настоящим пилотом удалите технические результаты. Держите открытым README репозитория. На платформу сдаётся ссылка на публичный GitHub, а не локальный адрес.

## Начало — около 40 секунд

«Меня зовут Молчанов Андрей Владимирович. Мой проект — CodeCoach, наставник по программированию для новичков. Проблема, которую я хочу проверить: получив готовое исправление, ученик может пропустить причину ошибки и повторить её в похожей задаче.

Для прототипа я выбрал один сценарий: ученик находит ошибку через тесты и постепенные подсказки, а затем решает похожую задачу самостоятельно. Это важнее для проверки идеи, чем сразу реализовать все экраны большой платформы».

## Демонстрация — около 2 минут

1. Покажите главную: задачи, текущий прогресс, маршрут от максимума к минимуму.
2. Откройте «Максимум в массиве» и нажмите «Проверить код».

«Здесь действительно выполняется JavaScript. На положительных числах стартовый код работает, а на отрицательных возвращает ноль, которого даже нет во входном массиве».

3. Откройте первую подсказку.

«Наставник сначала задаёт вопрос и показывает конкретный неудачный пример. Полное решение доступно только на четвёртом шаге. В этой версии наставник работает на правилах по результатам тестов. Внешняя AI-модель пока не подключена. Прототип проверяет формат обучения, а не качество конкретной модели».

4. Измените `let max = 0;` на `let max = numbers[0];`, повторите проверку.

«Теперь проходят все шесть проверок. За решение с одной подсказкой начисляется 80 XP. Повторный запуск не увеличивает награду».

5. Перейдите к минимуму. Для короткой демонстрации введите:

```javascript
function findMin(numbers) {
  let min = numbers[0];
  for (const number of numbers) {
    if (number < min) min = number;
  }
  return min;
}
```

«Вторая задача проверяет перенос идеи. Здесь нет подсказок. В исследовании код пишет участник, а я сейчас показываю только работу сценария».

6. Откройте результаты, покажите попытки, время, глубину помощи и JSON-экспорт. Не называйте собственную демонстрацию результатом пользовательского исследования.

## Гипотеза и следующий шаг — около 50 секунд

«Для первого пилота я выбрал следующий порог: минимум пять участников, из которых не менее 60% исправят первую задачу за десять минут без открытия ответа и затем решат вторую без подсказок. Приложение считает этот сценарий по действиям пользователя.

Пока это план исследования, а не подтверждённая эффективность. Следующий шаг — провести пилот со студентами и разобрать причины затруднений. После этого сравнить формат с готовым ответом в контрольной группе и проверить LLM-наставника».

## Разработка с агентом — около 30 секунд

«Я использовал Codex для сборки локального веб-прототипа по своему описанию и презентации. Агент подготовил интерфейс, запуск кода, тесты, хранение прогресса и README. Архитектура использует стандартный Node.js и браузер без внешних зависимостей. В репозитории есть автоматические проверки и инструкция запуска».

## Вопросы преподавателю

- Достаточно ли задачи на минимум для первой проверки переноса навыка, или лучше взять другую структуру задачи?
- Какие признаки понимания стоит добавить к успешным тестам и объяснению своими словами?
- Когда разумнее подключать LLM: до первого пилота механики или после него?

## Короткие ответы

**Почему наставник пока на правилах?** Чтобы локально проверить полезность постепенной помощи без ключей и зависимости от внешнего сервиса. Для проверки качества AI потребуются подключение модели и отдельный эксперимент.

**Чем отличается от готового ответа в обычном чате?** Ограниченной глубиной помощи, реальными тестами и самостоятельной следующей задачей. Преимущество такого подхода ещё нужно доказать.

**Что ограничивает прототип?** Четыре учебные задачи, фиксированные подсказки, локальные данные, отсутствие аккаунтов. Успешные тесты сами по себе не доказывают понимание.

**Это командная работа?** В материалах указан один участник. Не заявляйте о совместных обсуждениях и тестировании, если их не было. Если есть команда, добавьте её фактический состав и вклад до сдачи.
